01 / The useful question

Is the search losing matches,
or is the model answering badly?

An AI assistant first retrieves documents, then uses them to answer. Compression and approximate indexes make retrieval cheaper, but can leave out close matches. Cairn gives that first step a reference answer you can inspect.

02 / The mechanism

Cheap scores.
Careful decisions.

Cairn scans compact int8 vectors, calculates an upper bound on each full score, and checks the originals only where they could still change the answer.

Synthetic scores illustrate the pruning rule, not a benchmark or a browser port of the Rust engine. Production uses a larger seed shortlist. When bounds cannot rule candidates out, Cairn checks more originals, up to all of them.

Show the bound and the implementation

Let a be the compressed dot product and e the norm of the quantization residual.

full_score ≤ a + e_query × ‖document‖
               + ‖compressed_query‖ × e_document
               + floating_point_guard

A row is skipped only when this upper bound is strictly below the current kth full score. Equality stays eligible.

The real-arithmetic bound follows from Cauchy–Schwarz. The implementation adds conservative floating-point guards and uses a defined float64 scoring order over normalized float32 vectors.

This is a documented arithmetic contract, not a machine-checked proof. Read the algorithm and limits ↗

05 / Evidence, with the tradeoffs

A useful result.
A bounded claim.

On one Apple M3 Pro, Cairn matched all 2,124 tested rankings. Performance depends on dataset, query batching and how many candidates remain ambiguous.

Apple M3 Pro · warm cache · one CPU thread for FAISS

Exact top-10 agreement…

Index on disk…

Where the result holds. Single-query CPU search on static corpora, with exact recovery under the scoring contract. All compressed rows are scanned.

Where to choose something else. FAISS batching wins on our smaller datasets. Approximate search can be faster when some misses are acceptable. Near ties can force a full scan of originals.

What is not established. Production adoption, concurrent load, cold-cache performance, live Embed 5 behavior, or a hard RAM limit. The index stores originals and is larger than float32 alone.

Ordinary int8 search with a 4x candidate budget recovered every neighbor on these five datasets and was faster than certified search. It fails the committed synthetic near-tie regression; the bound check handles that case by doing more work.

06 / Under the hood

A small engine, built close to the machine.

src/kernel.rs

Integer SIMD

ARM NEON/SDOT and x86 AVX2 kernels selected at runtime, with a scalar fallback. Explicit accumulator and tail handling.

src/storage.rs

Memory-mapped snapshots

One immutable index, checked offsets, deep invariant validation and atomic publication. Originals are read where needed.

src/search.rs

Auditable decisions

Residual bounds, deterministic ties and exact fallback. Per-query counters expose the work, cutoff and largest pruned bound.

Working engineering prototype. Exactness refers to normalized stored float32 vectors and a fixed float64 scoring order. Existing work includes FAISS, Cohere BinaryVectorDB, SQLite-vec and RaBitQ. Cairn does not claim a new quantization algorithm.
